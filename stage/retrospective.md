# 项目复盘案例：某面板数据分阶段交付项目

> **业务线**：量潮数据（数据工程项目） ｜ **周期**：约半年（分阶段交付） ｜ **状态**：已交付待验收
> **角色**：商务经理 1 人 ｜ 软件工程师 1 人 ｜ 客户为外部学术研究者

**案例标识**：外部学术客户的面板数据项目；基于外部公开渠道获取的历史数据集；交付用户×日期粒度的行为面板与若干新增统计指标；项目分阶段推进，后一阶段为指标扩展。

---

## 一、项目概况

**交付范围**：

- **前期**：基于历史数据集，为一批用户交付按用户 × 日期组织的行为面板，并保留和交付代码。
- **后期**：在已有面板上增加若干新指标——一组"事件计数"类指标（区分全生命周期与一年窗口、总数与有效数），一组需要按"发起者归属"拆分的合并类计数指标，另增加数据可观测窗口信息。

**交付物**：更新的面板数据、代码交付集、代码逻辑说明书。

**验收标准要点**：面板按用户 × 日期输出；计数口径沿用最终面板名单、来源统计全平台；"有效事件"定义为与特定基准日同日发生；数据截止日约束下一年窗口按右删失处理；拆分指标按发起日期统计，通过数据表间的归属关系判定归属方。代码、数据和逻辑说明书一并交付。

## 二、项目过程（关键节点）

| 阶段 | 事件 |
|---|---|
| 前期交付 | 面板交付；客户确认付清款项并要求保留代码；团队发送代码及说明文档 |
| 后期需求 | 客户确认新增指标需求；确认计数来源口径与数据截止约束 |
| 方案澄清 | 第一版策划书误解指标口径，客户提供中文变量定义、算例和构建流程；团队当日更新方案 |
| 多轮口径修正 | 客户逐项修正有效事件定义、数据来源、拆分判定、窗口边界、时区和验证要求 |
| 报价与交付 | 修订报价明细，客户接受；发送代码数据包、逻辑说明书和最终面板数据；按客户补充说明更新交付包 |
| 收尾 | 跟进验收与付款；客户表示将在当周内审核反馈（截至复盘时点，最终验收结论缺失） |

## 三、复盘发现

### 沟通与流程

**需求传达偏差（最主要教训）**：

- 第一版策划书把两个相关但不同的计数口径误写成合并口径，且未一开始区分"来源侧计数"与"目标侧筛选"两类口径——客户审阅时才发现，方案返工
- 口径最终靠客户主动提供变量定义、算例和构建流程才对齐——**依赖客户纠正而非主动澄清**

**数据交接断点**：

- 团队没有长期保留项目原始数据的本地备份，且数据源一度不可用，被迫评估替代获取方案
- 最终由客户提供原始数据后才回到正确路径——**历史项目数据资产未沉淀，直接造成返工风险**

**合同与验收**：

- 后期详细技术验收口径靠邮件附件、算例和即时通讯补充说明逐项拼合，没有一开始就固化为完整验收文档
- 现有资料中缺失完整签署版合同文本，合同条款复盘无法完整进行——**项目商务档案完整性不足**

**响应时效与表达方式**：记录缺失，复盘时无法统计（数据收集不完整项）。

### 实操（技术）

**技术方案要点**（沉淀价值最高）：

- 多张数据表统一到用户 × 日期面板的推导链：最终名单匹配用户标识 → 通过归属关系推导目标对象与关联关系 → 结合行为记录判断"同日有效"事件
- 拆分指标的归属判定：通过数据表间的归属键关联判定，**不使用历史事件表中缺失严重且不可靠的操作者字段**
- 时间处理统一 UTC；数据截止约束下一年窗口按右删失处理并保留可观测窗口信息

**资源卡点**：大体量外部数据源无本地备份 + 数据源一度不可用 = 数据可得性风险；曾评估多种替代获取与处理方案。

**协作卡点**：项目中途更换对接人、多方代发信息，增加同步成本；关键口径靠客户补充说明闭环。

**工具链卡点**（CLI 复现）：复现过程中记录了 5 个已确认问题，清单已回流产品侧跟进。

## 四、沉淀的改进方向

| 方向 | 具体措施 |
|---|---|
| 需求澄清前置 | 涉及统计口径的需求，第一版方案前先产出"口径确认单"（变量定义+算例+边界条件），客户确认后再写策划书 |
| 数据资产沉淀 | 项目原始数据与获取渠道记录入库，避免"数据源不可用无备份"重演 |
| 商务档案完整 | 合同签署版、验收文档强制归档，复盘可追溯 |
| 验收标准前置 | 技术口径在策划书阶段固化为可验证的验收文档，不靠后续补充说明拼合 |
| 工具链反馈 | CLI 复现问题清单回流产品侧跟进 |

## 五、案例启示（对内）

- **统计口径类需求必须用算例对齐**：文字描述的口径在双方脑中可以完全不同，算例是唯一无歧义的载体
- **数据密集型项目的历史数据资产是隐性风险**：不沉淀数据，等于把命运交给外部数据源的存续
- **验收标准前置**是统计类交付项目的核心流程改进点：口径确认单 → 策划书 → 合同验收条款，逐层固化
